# x86-64

## Select the ABI

| Property | System V AMD64 | Windows x64 |
|---|---|---|
| Integer arguments | `rdi, rsi, rdx, rcx, r8, r9` | `rcx, rdx, r8, r9` |
| Floating arguments | `xmm0`–`xmm7` | `xmm0`–`xmm3`, matched to argument position |
| Integer return | `rax`, sometimes `rdx:rax` by classification | `rax` |
| Stack provision | 128-byte red zone in eligible user-space code | Caller reserves 32-byte shadow space; no red zone |
| Nonvolatile GPRs | `rbx, rbp, rsp, r12`–`r15` | `rbx, rbp, rdi, rsi, rsp, r12`–`r15` |

For exact aggregate, vector, variadic, unwind, and return-value rules, use the active ABI specification. At a System V function entry, the return address means `rsp` is eight bytes away from a 16-byte boundary. Windows requires 16-byte alignment outside prolog and epilog regions.

## Inspection commands

```sh
gcc -O2 -S -masm=intel source.c -o source.s
clang -O2 -S -masm=intel source.c -o source.s
llvm-objdump -d --x86-asm-syntax=intel binary
rustc -C opt-level=3 --emit=asm source.rs
```

With MSVC, use `/FAs` for an assembly listing and `dumpbin /disasm` for a built object or image. Keep compiler-generated unwind directives intact when writing functions that can participate in exceptions or stack walking.

## Frequent mistakes

- Mixing Intel destination-first syntax with AT&T source-first syntax.
- Treating `r8`–`r11` as four additional System V argument registers; only `r8` and `r9` are the fifth and sixth integer argument registers.
- Forgetting that a 32-bit GPR write clears the upper 32 bits, while 8- and 16-bit writes do not.
- Assuming `lea` reads memory; it computes an address expression.
- Using the red zone in kernels, interrupt-sensitive code, or Windows code.
- Calling through an unaligned stack or omitting Windows shadow space.
- Mixing legacy SSE and AVX code without accounting for transition costs on affected processors.
